# InvMenu 4.7.6 — Bedrock virtual inventory close handshake

## What changed

- Corrected virtual inventory opening for RyzeMP: InvMenu no longer sends a
  forged client-response `ContainerClosePacket(server=false)` on every tick.
- The actual `ContainerOpenPacket` is followed, on the next server tick, by a
  `NetworkStackLatencyPacket` request. A matching echo confirms *network
  ordering*, not guaranteed UI rendering. Failed or late echoes are handled
  by the existing bounded timeout/cleanup flow.
- Actual Bedrock `PacketViolationWarningPacket` messages are no longer
  intercepted as fake inventory ACKs. This eliminates the known source of
  repeated `Server sent a ContainerClosePacket response packet` warnings
  from `/settings` and other InvMenu-based virtual chests.
- Failed openings no longer call the core's `onClientRemoveWindow()` to
  simulate a client close. Server-initiated closes remain managed by the
  native PocketMine/RyzeMP inventory lifecycle.
- Compatible public PHP namespace, Composer package name and menu types.
  This library is not a standalone plugin for `plugins/`.

## Validation

- Regression suite: tests for protocol warnings, hopper menus, open-once
  behavior, matching latency echoes, stale replies, timeout, reentrancy,
  transaction cancellation and graphics cleanup.
- Matrix: PHP 8.1, 8.3 and 8.4; PocketMine and RyzeMP World APIs.
- Clean Composer consumer test against the published RyzeMP dependency.
- **Before release, still test in real Bedrock clients 1.26.40 and 1.26.60**:
  `/settings` repeated fast toggles, `/scoreboard`, 27/54-slot chests, hopper,
  `/ec` (shared inventory), cancel/close, teleports and disconnects.
  The automated suite does not simulate rendering or client-side animations.

## Owner's release procedure (after client validation)

1. Merge [PR #2](https://github.com/RyzeCompany/InvMenu/pull/2)
   into the `pm5` branch; keep the version bump in the tag, not in
   `composer.json`.
2. In GitHub → **Releases → Draft a new release**, create tag `v4.7.6`
   **targeting `pm5`**, and publish it.
3. Wait for the repository's release workflow and Packagist to index
   `ryzecompany/invmenu` version `v4.7.6`.
4. In HardCoreFactions, update the Composer dependency to `^4.7.6`,
   update `composer.lock` from Composer and rebuild/test the PHAR.
   The HCF PHAR includes a shaded copy of InvMenu, so publishing the
   library alone does **not** update existing HCF deployments.

No modifications to HCF or RyzeMP are included in this InvMenu release.
